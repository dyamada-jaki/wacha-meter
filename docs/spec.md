# わちゃメーター 仕様

最終更新: 2026-11-07。ユーザーから確認できた構想と未決事項を記録する。調査上の提案は [初期調査](research/feasibility.md) に分ける。接続方式・採点式は未採用。

## 1. これは何か

集まったメンバーがどれくらい「わちゃわちゃ」しているかを測るアプリ。
Zoom などのオンライン会議ツールに1参加者として参加して様子を観測し、会議終了時に「わちゃわちゃ」の度合いをスコアとして参加者に知らせる、という体験を目指す。

最初に実現方法を調査し、その結果から試作・開発を進める。Web アプリ、デスクトップアプリなどの実装形態はまだ決まっていない。

## 2. 中身

現時点で確認できた利用の流れ:

1. オンライン会議にわちゃメーターが参加する。
2. 集まっているメンバーの「わちゃわちゃ」を観測する。
3. 会議終了時にスコアを参加者に知らせる。

他の人が主催する会議への参加が必要。主催者とユーザーが同じ Zoom 契約に属するかは不明なので、別アカウント主催の会議も対象にして成立条件を検討する。

会議には「わちゃメーター」が1参加者として入る。録音ファイルの解析だけに置き換えず、まずボットの入室と音声取得を優先して検証する。

招待方法、観測データ、スコアの範囲・計算式、結果の通知先・通知手段は未決。会議全体に対するスコアを構想の出発点とし、個人別の採点は依頼されていない。

## 3. 決まりごと

- 仕様の言語は日本語。
- 費用条件: 無料でできる構成を基本とする。ただし、Zoom の有料アカウントで実現できる構成は候補に含めてよい（ユーザー確認済み）。Zoom の契約費とアプリの追加費用を分ける。有料ボット API・有料 AI API・有料サーバーは前提にしない。期限付き無料体験だけで継続利用できるとは扱わない。
- 最初の試作は今使っている Mac で動かす（ユーザー承認済み）。接続試作は開発時と実行時の両方で、既存の OrbStack / Docker 上の ARM64 Linux を使う。完成版の Docker 利用・配布形態・最終方式は未決。
- 「わちゃわちゃ」の定義はユーザーとの議論で決める。音量・発言量・楽しさを同一視した採点式を推測で実装しない。
- 会議への参加方法は各サービスの公式仕様に基づいて検討する。
- 実会議の音声・映像・文字起こし・参加者情報・参加 URL・認証情報を公開リポジトリに保存しない。
- 観測の告知・許可、外部サービスへの音声送信、保存期間は実会議検証前に決める。

## 4. 区切り

### 区切り1: Zoom に別参加者として入り、音声を取得する試作

2026-11-07 にユーザーが範囲を承認した。

- 対象: Zoom。他の人が主催する会議を対象とする。同じ契約内か不明のため、外部アカウント主催の場合も成立条件に含める。
- 実行環境: 今使っている Mac。
- 費用: 無料で開始。Zoom の有料会議プランが必要と分かった場合は、理由を提示して相談する。追加課金 API・Developer Pack を前提にしない。
- 達成の確認: 主催者の参加者一覧に本人とは別の「わちゃメーター」が表示され、主催者の許可後に音声データを取得できる。その後退出できる。
- 待機室で待つだけ、入室だけ、手元の録音ファイルを解析するだけでは、この区切りを達成したと扱わない。
- 現状: ARM64 Linux の開発環境を構築し、C++ のビルド・実行と仮想音声デバイスを確認済み。Linux ARM64 Meeting SDK 7.1.5.4434 をユーザーが入手し、SDK 本体の AArch64 ELF とヘッダーの存在を確認した。SDK のビルド・初期化・認証・実会議検証は未実施。開発用アプリの認証情報設定、用途・外部会議のテスト条件は未確認の部分が残る。

作業の順序は SDK 入手とビルド → 初期化・認証 → 外部会議用のテスト条件を満たす → 入室 → 許可を受けて音声取得 → 退出。個別問い合わせは準備作業の開始条件にしない。

### 以降の区切り（案・未採用）

音声取得の見通しが立った後に、わちゃわちゃの指標・採点方法と画面デザインを決める。その後、短い会議での指標を参加者の実感と照らし、会議終了後の結果提供までつなぐ。

### 今はやらないこと

調査段階では、本番会議への接続、採点式の確定、課金サービスへの契約・課金実行を行わない。
