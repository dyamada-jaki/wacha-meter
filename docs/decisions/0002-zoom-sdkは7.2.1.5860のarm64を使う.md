# 0002. Zoom Meeting SDK は 7.2.1.5860（Linux-all バンドルの arm64）を使い、JWT の有効期間は 3600 秒にする

- 状態: 採用
- 日時: 2026-11-09 00:00 JST
- 関連: Issue #1 / 採用 PR #2 / [Issue レポート](../issue-reports/issue-1.md)

## 背景
Issue #1 は、Linux ARM64 版の SDK 7.1.5.4434 で始めた。初期化とダミーの認証情報での認証は通ったが、本物の認証情報では `SDKAuth` の結果が返らず（`GetAuthResult` は `AUTHRET_NONE` のまま。5回再現）、認証を確かめられなかった。

## 決定
- SDK は Marketplace の「Linux-all」バンドル `zoom-meeting-sdk-linux-7.2.1.5860.tar.xz` の `arm64/` だけを使う。SHA-256 を照合し、AArch64 の ELF であることを確かめてから `.local/zoom-sdk/7.2.1.5860` に展開する（`prototypes/zoom/scripts/prepare-sdk.sh`）
- ARM64 版の 7.1.0 / 7.1.5 は使わない
- SDK に渡す JWT の有効期間（exp − iat）は 3600 秒にする

## 理由
- 7.2.1.5860 にすると、本物の認証情報で認証に成功した（2026-11-08、PR #2 の `b015f2b`）
- Zoom 開発者フォーラムに、Linux arm64 の 7.1.0 / 7.1.5 だけで同じ症状が起き、7.2.1.5860 で解消したという報告がある（[報告](https://devforum.zoom.us/t/linux-arm64-meeting-sdk-7-1-0-7-1-5-sdkauth-never-calls-back-7-0-5-arm64-and-7-1-5-x86-64-work/146972)）。7.1.5 の不具合が原因というのは、この報告に基づく推測で、SDK の内部は確かめていない
- 「Linux-arm64」のダウンロード欄は 7.1.5 が最新と表示されるので、7.2.1 は「Linux-all」から取る必要がある
- 公式資料では JWT の有効期間の最小は 1800 秒だが、手元の実測で 7.1.5 は 1800 秒、7.2.1 は 1800・1801 秒の JWT をその場で拒否した。余裕をもって 3600 秒にする（上限は 48 時間）

## 選ばなかった案
- 7.1.5.4434 のまま進める: 本物の認証情報で認証できないため
- 7.0.5 の arm64 に戻す: フォーラムでは動くと報告されているが、古い版で、今後の修正を受けられないため
- x86_64 の SDK をエミュレーションで動かす: 手元の ARM64 環境で動く版があるため

## 影響
- 次の Issue でも `.local/zoom-sdk/7.2.1.5860` を使う。新しい版に替えるときは、準備スクリプトの SHA-256・既定の場所・README を直し、本物の認証をもう一度確かめる
- 展開スクリプトのシンボリックリンクの検査（絶対パスや `..` を含むものを拒否）は、この決まった SDK に合わせたもので、どんなアーカイブにも安全とは保証しない
- 見直すきっかけ: Zoom が新しい版を出したとき、または「Linux-arm64」のダウンロード欄が更新されたとき
