## 後続 Issue の候補（未登録）

### 入室検証の前提: 外部会議のベータテスト経路を具体化する

- 他者主催の会議への参加が必要。共通契約かは不明なので外部アカウント主催を含める。
- OBF 認証資料にはボット参加の手順がある一方、Meeting SDK の用途説明はボット非対応としている。用途・審査条件を確認するまで方式を採用しない。
- 主催者の録音許可とアプリの審査・認証は別条件。通常の Zoom 有料プランだけで解消するとは仮定しない。
- Zoom の公式ベータテスト手順には、外部会議用の認可 URL 共有申請がある。開発用 General App と SDK の準備は済んだ。個別問い合わせは開発準備の開始条件にしない。次は Local Test / Beta Test の条件を具体化する。外部会議への接続に必要な承認は別途満たす。
- 根拠と未確認事項は [初期調査](research/feasibility.md) に記録した。問い合わせ文は予備として保持するが、未送信。Notta の参加者型ボットは参考例であり、新規アプリが同じ条件で使える証拠とは扱わない。

### 条件が解消した後の候補: 「わちゃメーター」が Zoom の参加者一覧に表示されることを確かめる

- 目的: SDK で作った独立したボットが Zoom に入室できるかを、最初に小さく確かめる。
- 仕様: [spec.md](spec.md)。検証の段階は [初期調査](research/feasibility.md#最初の接続検証の具体案)。
- 前提: SDK の用途・審査条件が確認でき、対象会議に参加可能な認証を用意できること。主催者が協力できること。SDK の入手・実認証は完了したが、外部会議での方式の成立条件は未確認。
- 受け入れ条件案:
  - 主催者の参加者一覧に、ユーザー本人と別の「わちゃメーター」が表示される。
  - 待機室での待機と入室成功を区別できる。入室に失敗した場合は成功と扱わない。
  - 退出でき、検証後に接続を残さない。
  - 秘密情報を公開リポジトリやログに残さない。
- スコープ外: 音声解析・採点・結果通知・不特定多数への公開。外部主催会議の参加自体は検証対象。
- 続く候補: ホストの許可を受けた音声取得 → 参加者別の音声と時刻の確認。入室成功だけで音声取得まで成功したとは扱わない。
- 現在の扱い: 未決条件を確認してから Issue を具体化する。Issue 登録・「開発可」付与・実装はまだ行わない。
